## Intuition / Theory

### Generation Evaluation
Traditional metrics like BLEU and ROUGE rely on lexical overlap (matching exact words). For LLMs, these are often inadequate because a generated response can be perfectly correct but use completely different vocabulary than the reference. 
*Modern approach:* Semantic similarity (embeddings) and LLM-assisted evaluation.

### RAG Evaluation Triad
Evaluating RAG systems requires assessing both the retrieval and the generation components:
1. **Context Relevance (Retrieval):** Is the retrieved context actually relevant to the user's query?
2. **Groundedness / Faithfulness (Generation):** Is the generated answer fully supported by the retrieved context? (Checking for hallucination).
3. **Answer Relevance (Generation):** Does the generated answer directly address the user's original query?

### LLM-as-a-Judge
Using a powerful LLM (like GPT-4) to evaluate the outputs of another model. You provide the evaluator LLM with a grading rubric, the query, the context, and the answer, and ask it to output a score and a reasoning trace.

## Interview Questions
1. **Explain the RAG evaluation triad.**
   *Answer:* It consists of Context Relevance (is retrieved info useful?), Faithfulness/Groundedness (is the answer derived only from context?), and Answer Relevance (does the answer satisfy the user query?).
2. **Why use LLM-as-a-judge instead of human evaluation?**
   *Answer:* Human evaluation is expensive, slow, and hard to scale. LLM-as-a-judge correlates reasonably well with human judgment, is scalable, and enables automated, continuous evaluation in CI/CD pipelines.
3. **What is a major risk of using LLM-as-a-judge?**
   *Answer:* The evaluator LLM might have biases (e.g., preferring longer answers, or answers generated by its own model family) and can still hallucinate or misunderstand complex rubrics.
